A00Admin Conventions

Everything from the rider contract's module 00 still applies — envelope, error codes, pagination, money and time formats. What follows is what is different about an internal surface.

  • Prefix. /api/v1/admin/…, separated from the app surfaces so it can sit behind its own gateway, its own rate limits and its own IP allowlist.
  • Separate identity. Admins are not users. Staff accounts live in their own table with their own tokens; a rider or driver token must never authenticate against /admin/*. Return 403 NOT_STAFF, not 401, so the console can tell the two apart.
  • 2FA is mandatory for any role that can move money. The login response carries requires_2fa and the console holds the flow.
  • Scoped permissions. Every endpoint declares a permission string (trips.refund, wallets.adjust, kyc.approve, pricing.write, staff.manage). Return the caller's full permission set from /admin/me so the console can hide what they cannot do — and still enforce it server-side, because hiding a button is not security.
  • One trip, one id. A trip is trip_id (trp_ prefixed) on all three surfaces — rider app, driver app and this console. /admin/trips/{id} takes that value, and the rider-facing code (ZR-4801) is a display label only, never a key. The SHARED appendix in the rider and driver contracts defines how the one trip state machine projects into each app's view.
  • Market scoping. Every request carries X-Market: ci|ng (or ?market=). A staff account is scoped to one or more markets; cross-market reads need an explicit global permission.
  • Every write is audited. Actor, action, target, before/after, IP, request id — written synchronously, in the same transaction as the change. If it is not in the audit log it did not happen.
  • Reason strings are required on destructive or financial writes (suspend, refund, adjust, reject). They are shown to the affected user and stored on the audit entry, so validate them as non-empty and length-bounded.
  • Idempotency on everything that moves money, same as the app surfaces.
  • Every list endpoint supports ?page, ?per_page, ?q (free-text), ?from/?to, the filters named in its module, and ?format=csv for export. The console's tables already assume all of these.
  • Long jobs return a job, not a payload. Exports and bulk actions respond 202 with { job_id, status_url }; the console polls or receives job.completed.

List envelope with facet counts

The console renders filter chips with counts (“Failed (12)”) beside every table. Those counts must come from the server or they will disagree with the filtered result on page 2.

Session bundle and /admin/me

The console needs the resolved permission set — not the role name — because permissions can be granted or revoked per person on top of a role (A20).

{
  "access_token": "eyJ…", "expires_in": 900,
  "refresh_token": "rt_…", "refresh_expires_in": 43200,
  "staff": {
    "id": "stf_001", "name": "A. Otitoju", "email": "admin@zenride.app", "phone": "+234 803 …",
    "role": { "key": "super_admin", "label": "Super admin", "rank": 100 },
    "permissions": ["dashboard.view", "trips.refund", "wallets.adjust", "staff.manage", …],
    "permission_overrides": { "granted": ["pricing.write"], "revoked": [] },
    "markets": ["ci", "ng"],
    "twofa_enabled": true,
    "must_change_password": false,
    "status": "active"
  }
}
Rank is part of the contract, not a UI detail.

"Admins can manage admins" is only safe if it is directional. Every account carries a numeric rank; an actor may act on accounts strictly below their own rank and never on their own. Ship the rank in this payload so the console can explain a refusal, and enforce it again on every staff route — otherwise any admin can promote themselves to super admin in one request.

Move the session to an httpOnly cookie.

The console currently keeps its token in localStorage, which means the route gate is client-side only. Set the refresh token as httpOnly; Secure; SameSite=Lax and the console can reject unauthenticated requests at the edge, before any HTML is served.

A19Staff Management screen: Staff & roles

Super admins and admins can act on any lower-ranked admin: edit their details, change their role, grant or revoke individual permissions, reset their password, and suspend or block them. Every route below re-checks both the permission and the rank.

Shared preconditions

  • Permission. staff.manage for details, role and permissions; staff.password for the password routes; staff.revoke for suspend, block and reinstate.
  • Rank. actor.rank > target.rank, except a super admin who may act on any account. Reject with 403 INSUFFICIENT_RANK and a message naming the target's role, so the console can say why.
  • Never yourself. Any of these routes aimed at actor.id returns 403 CANNOT_TARGET_SELF. Own password and own sessions go through /admin/me/*.
  • Never the last one. Refuse the change if it would leave zero active super admins — 409 LAST_SUPER_ADMIN.
  • Reason required on every route that removes access or sets a credential; stored on the audit entry and, where the person is notified, shown to them.
MethodPathPurposeNotes / payloadKind
GET/admin/staffAdmin directory.Filters status=active|suspended|blocked, role, market, twofa, q. Each row carries role with its rank, permission_count, override_count, twofa_enabled, markets, last_active_at, and can_manage — a server-computed boolean saying whether this caller may act on that row, so the console does not re-derive the rank rule.Read
GET/admin/staff/{id}One admin.Adds resolved permissions[], permission_overrides (granted / revoked), session list, and their last 50 audit entries — you should be able to see what someone has been doing before you change what they can do.Read
POST/admin/staff/inviteCreate by invitation.name, email, phone, role, markets[]. The invitee sets their own password from a single-use link (48h). Never accept a password here. The assigned role must be below the inviter's rank.Write
PATCH/admin/staff/{id}Edit details.name, email, phone, markets[]. An email change is a sign-in change: notify both the old and new address, and require re-verification before the new one works.Write
PUT/admin/staff/{id}/roleChange role.role, reason. Only roles strictly below the actor's rank are assignable — return that list from /admin/roles filtered per caller. Changing a role clears per-person overrides by default; accept keep_overrides=true to opt out, and say which happened in the response.Write
PUT/admin/staff/{id}/permissionsGrant or revoke individually.granted[], revoked[], reason. These layer on top of the role: effective set = role permissions + granted − revoked. An actor can never grant a permission they do not themselves hold — 403 CANNOT_GRANT_WHAT_YOU_LACK, which is what stops privilege laundering through a subordinate account.Write
POST/admin/staff/{id}/password/reset-linkSend a reset link.The preferred path: the admin sets their own password, nobody else ever knows it. Sets must_change_password, revokes their sessions, emails a single-use link.Write
POST/admin/staff/{id}/password/setSet a temporary password.password (min 12), reason. For a locked-out colleague. Must force must_change_password=true, revoke every session, and notify the account holder that you did it and why. Consider restricting this route to super_admin.Write
POST/admin/staff/{id}/2fa/resetClear 2FA enrolment.For a lost device. Re-enrolment is forced at next sign-in. High-value target for social engineering — require a reason and notify the holder.Write

POST/admin/staff/{id}/blockBlock access.reason. Revokes every session, refuses sign-in, and invalidates any pending invite or reset token. Prefer this to deletion so past actions stay attributed.Write

DELETE/admin/staff/{id}Hard delete.Only for an account created in error. Refuse once the account has any audit entries — 409 HAS_AUDIT_HISTORY, block them instead. Deleting an actor would orphan the trail that makes the log worth keeping.Write
GET/admin/rolesRoles and their permissions.Per role: key, label, rank, description, permissions[], member_count, and assignable_by_me. Seeded roles: Super admin 100, Admin 90, Operations 60, Finance 60, Compliance 50, Support 40, Read only 10.Read

A25Security Requirements

This surface can move money, read identity documents and message every user. It needs more than the app surfaces do.

  1. Separate staff identity and 2FA. Own table, own tokens, TOTP required for any money-touching role. Short access tokens (15 min).
  2. Enforce permissions server-side on every route. The console hides what a role cannot do; that is UX, not security. Every handler checks its own permission string.
  3. Audit every write synchronously, in the same transaction, with before/after. An action that succeeds but fails to audit must roll back.
  4. Second approver above a threshold for wallet adjustments, write-offs and surge overrides. One compromised support account should not be able to drain a float.
  5. Signed, expiring URLs for documents, and audit each access. KYC files are NIN/BVN-grade identity data.
  6. Rate-limit and IP-allowlist the admin surface. It has no reason to be reachable from the whole internet.
  7. Never return secrets. Integration credentials are write-only; masked everywhere else. Bank accounts show last four only.
  8. Redact by default in list views. Full phone numbers and full account numbers require a permission and produce an audit entry — support does not need them to answer most tickets.
  9. Idempotency on every money write, and make double-approve of a payout provably safe.
  10. No delete routes on the audit log. Append-only, exportable, retained.

A26What Exists Already

The console is built and running against fixtures, so these shapes are not theoretical — a working UI already consumes them.

  • Stack. Next.js 15 App Router, React 19, TypeScript. No CSS framework, no chart library, no component kit. Typecheck and production build clean; every route smoke-tested.
  • Login is the entry point. /login handles credentials then the 2FA step; every console route sits behind a session gate and returns you to the screen you asked for. Demo mode ships a directory of accounts, one per role, so the RBAC rules can be seen working.
  • RBAC is enforced in the UI. 43 permissions in ten groups, seven ranked roles, per-person grants and revocations on top of a role. The sidebar hides what you cannot view, the dynamic route refuses a typed URL, row actions are filtered before render, and a refusal explains itself ("Only a super admin can act on an admin"). All of it still needs server-side enforcement.
  • Staff management is complete against this contract. Edit details, change role, grant and revoke individual permissions, send a reset link or set a temporary password, reset 2FA, revoke sessions, suspend, block, reinstate — each bounded by rank and refusing self-targeting.
  • Realtime is wired. A read-only channel per market drives the sidebar badges, the Live ops event stream and a critical-event banner. Mock mode emits events on a timer; live mode opens a socket after /admin/realtime/auth.
  • The map is built as a tile-free SVG projection of zone centres with live driver dots, so it needs no map key. It consumes /admin/ops/drivers-online exactly as specified above.
  • One seam. src/lib/api.ts is the only file that talks to the network. loadSnapshot() fans out to the list endpoints here; actions.* name the write endpoints. Flip NEXT_PUBLIC_USE_MOCKS, point the base URL, delete the fixtures.
  • Still client-side only: the session lives in localStorage, so the route gate is not enforceable at the edge. Moving the refresh token to an httpOnly cookie is the one change needed before this is exposed outside the team.
